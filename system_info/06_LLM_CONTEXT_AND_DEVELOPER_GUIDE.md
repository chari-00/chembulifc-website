# 06 — LLM Context & Developer Handbook

This guide is specifically designed for **AI Agents / Large Language Models (LLMs)** and **human developers** operating on the Chembuli FC codebase. It outlines invariants, architectural dogmas, pitfalls, and step-by-step procedures for extending the application.

---

## 1. Absolute Golden Rules (System Invariants)

When working on this repository, you must observe these strict constraints:

> [!CAUTION]
> **1. PROTECTED DIRECTORY: `logo/`**
> Never edit, overwrite, rename, or delete any file inside `c:\Users\hailq\Music\Chembuli\logo\`.
> This directory contains the original master brand assets.
> The active application crest is located at `website/src/assets/logo-alt.png` and `website/public/logo-alt.png`.

> [!IMPORTANT]
> **2. EVENT STATUS MUST NEVER BE STORED IN THE DATABASE**
> An event's status (`open`, `upcoming`, `completed`) is **purely derived** at runtime using the `eventStatus(event, now)` helper in `src/data/events.ts`.
> Never add a `status` field to `ClubEvent` or write a status string to persistent storage.

> [!IMPORTANT]
> **3. REGISTRATION REFERENCE UNIQUENESS & AUDIT**
> All registration reference codes must start with `CFC-` (e.g. `CFC-A4B7D2`) and must be generated via `registrationReference(existingRefs)` or `registrationReferenceWithFallback(existingRefs, isGloballyTaken)`.
> References must be verified against the global `reference_history` collection to guarantee cross-tournament uniqueness.

> [!IMPORTANT]
> **4. ROUTING CONVENTIONS**
> This project uses **TanStack Start** with **TanStack Router** file-based routing.
> - Do **not** create Next.js conventions (`app/layout.tsx`, `pages/`, `route.ts`).
> - The root shell is `src/routes/__root.tsx`.
> - Dynamic segment parameters use bare `$` syntax without curly braces: `events.$slug.tsx`, not `events.[slug].tsx`.
> - Layout files render children via `<Outlet />`.
> - `src/routeTree.gen.ts` is auto-generated by the compiler; never edit it manually.

> [!IMPORTANT]
> **5. UNIFIED DATA ACCESS & AUDIT LOGGING**
> All client-side data operations pass through `src/lib/store.ts` (`useDB`, `useLiveEvents`, `update`, `addRegistration`).
> Direct mutations to tournaments, registrations, gallery photos, and blog posts must dispatch to `logAdminAction(...)` (`admin_history`).
> Tournament registrations must dispatch to `logReferenceHistory(...)` (`reference_history`).

> [!IMPORTANT]
> **6. TRANSACTIONAL EMAILS VIA GMAIL SMTP**
> Confirmation emails must route through `sendRegistrationEmail` (`src/lib/email.functions.ts`) using Nodemailer and Gmail SMTP (`chembuli.fc@gmail.com`).
> Always preserve graceful degradation: return `{ sent: false, reason: "Email sending is not set up yet" }` when `GMAIL_APP_PASSWORD` is absent without throwing.

> [!IMPORTANT]
> **7. SUPER-ADMIN HARD-LOCK SECURITY**
> Account `chari` (and any user holding the `superadmin` label) is permanently protected against deletion or role demotion both in UI controls and on server functions (`deleteAdminFn`).

## 2. Common Workflows

### 2.1 Adding a New Public Page

1. **Create the Route File**:
   Inside `website/src/routes/`, create a new `.tsx` file (e.g. `about.tsx`).
2. **Define the Route**:
   ```tsx
   import { createFileRoute } from "@tanstack/react-router";

   export const Route = createFileRoute("/about")({
     head: () => ({
       meta: [
         { title: "About Us — Chembuli FC" },
         { name: "description", content: "History and ethos of Chembuli FC." },
       ],
     }),
     component: AboutPage,
   });

   function AboutPage() {
     return (
       <div className="mx-auto max-w-7xl px-5 py-20">
         <h1 className="text-5xl font-bold uppercase">About Chembuli FC</h1>
       </div>
     );
   }
   ```
3. **Verify the Route Tree**:
   Run `npm run build` or `npm test` to allow the TanStack Router Vite plugin to regenerate `src/routeTree.gen.ts`.
4. **Link in Navigation**:
   If needed in global navigation, add the entry to the `nav` array in `src/components/site/SiteChrome.tsx`.

---

### 2.2 Adding an Admin Management View

1. **Create the Route File**:
   Inside `website/src/routes/`, name the file prefixed with `admin.` (e.g. `admin.sponsors.tsx`).
2. **Define the Route**:
   ```tsx
   import { createFileRoute } from "@tanstack/react-router";

   export const Route = createFileRoute("/admin/sponsors")({
     component: AdminSponsorsPage,
   });

   function AdminSponsorsPage() {
     return (
       <div className="mx-auto max-w-7xl px-5 py-8">
         <h2 className="font-display text-2xl font-bold uppercase">Sponsors Management</h2>
       </div>
     );
   }
   ```
3. **Add Navigation Tab**:
   In `src/routes/admin.tsx`, append `<Link to="/admin/sponsors">Sponsors</Link>` to the header navigation.

---

### 2.3 Adding a Business Invariant / Validation Rule

1. Add the validator or pure computation function to `src/data/events.ts` or `src/data/blog.ts`.
2. Add corresponding test cases to `src/test/events-rules.test.tsx` or `src/test/blog-rules.test.tsx`.
3. Run `npm test` to verify all tests pass.

## 3. Styling & Aesthetics Dogma

- **Color Harmony**: Dark mode base (`bg-background` is `#0c0d0e`), vivid athletic primary green/emerald accents, crisp white headlines, and muted gray secondary text.
- **Athletic Geometric Cuts**: Use `clip-diag` for modern diagonal-cut buttons and panels.
- **Glassmorphism**: Use `glass` utility for floating headers, badges, and modals.
- **Glow Accents**: Use `glow` utility to highlight interactive primary buttons and cards.
- **Typography**: Athletic headers use `font-display` (Rajdhani), while readable body copy uses standard sans typography (Manrope).

## 4. Testing & Verification Checklist

Before completing any code modifications:

1. **Run Unit Tests**:
   ```bash
   cd website
   npm test
   ```
   Ensure all 6 test suites pass with 0 failures:
   - `src/test/csv-export.test.ts` (CSV generation, escaping, delimiter joining, column inclusion)
   - `src/test/email-dispatch.test.ts` (Nodemailer Gmail SMTP input validation, graceful degradation)
   - `src/test/events-rules.test.tsx` (Tournament status, fallback collision references, capacity, UPI proofs)
   - `src/test/blog-rules.test.tsx` (Draft vs published separation)
   - `src/test/superadmin.test.tsx` (Route matching, identifier normalization, deletion hard-locks)
   - `src/test/app-routing.test.tsx` (Route tree and slug pattern matching)

2. **Verify Production Build**:
   ```bash
   npm run build
   ```
   Ensures SSR compilation, client bundling, and Nitro Cloudflare preset bundle generate cleanly.

3. **Verify Logo Assets**:
   Ensure `SiteChrome.tsx` and `admin.tsx` continue to import `logo` from `@/assets/logo-alt.png` and no broken Lovable JSON CDN paths are introduced.
